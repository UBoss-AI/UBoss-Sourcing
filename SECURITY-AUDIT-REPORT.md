# UBOSS Security Audit Report

Audit date: 20 September 2026

Result: **Do not release this working copy to production yet.** The project has many good security controls, but the red and yellow items below must be handled. No source-code audit can guarantee that nobody will ever hack a system.

Scope reviewed: backend, all three web applications, scripts, dependencies and lockfiles, authentication, permissions, tenant isolation, payments, webhooks, uploads, database access, CI, nginx, systemd, deployment configuration, and the local development configuration. Secret values were not printed or copied into this report.

Status meaning: **Yes** = following; **Partly** = control exists but is incomplete; **No** = not following; **Not verified** = the repository cannot prove the live setting.

## Test evidence

- Production dependency audits: **0 known vulnerabilities** in backend, admin web, customer web, logistics web, and scripts production dependencies.
- Full dependency audit: **1 high** development-tool vulnerability in `scripts`; all other audited packages were clear.
- Focused backend security tests: **171 passed** — authentication, token rotation/reuse, TOTP, SSRF, payment security, signed carrier webhooks, and logistics tenant isolation.
- Frontend tests: **847 passed** across the three web applications, including **11 XSS sanitizer tests**.
- Backend type-check and lint: passed.
- Full backend test command: **passed** — typecheck, lint, 146 test files, and 2,789 tests.
- Local gitleaks, Semgrep, and Trivy executables were not installed. CI configuration was inspected, but its latest remote run was not available in this local audit.

## Standard used

The checklist is based mainly on the [OWASP Application Security Verification Standard 5.0.0](https://owasp.org/projects/asvs), the [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html), and [NIST Secure Software Development Framework SP 800-218](https://csrc.nist.gov/pubs/sp/800/218/final).

## Final decision

The repository-controlled hardening items in this report are implemented, and the complete backend verification gate is green. This is **not a production security sign-off**: live secrets, GitHub protections, ClamAV availability, TLS/firewall/DNS, backups/restore, incident readiness, and an independent penetration test remain external verification tasks.
